# Docstrings (PEP 257)
Applies to: function_length, naming

Every public function should have a docstring. Start with a one-line summary in the imperative mood ("Return the matching items."), then, if needed, a blank line and details about arguments, return value and raised exceptions. A docstring explains what and why; the code already shows how. If a function is hard to summarize in one line, it probably does too much.
